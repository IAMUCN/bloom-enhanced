### The release process, exactly (what was done, in order)
1. Work on a branch; commit each round (conventional commits, `Co-Authored-By` + `Claude-Session` lines). Gates before a release: `bun run build`, `bun test scripts/`, in `src-tauri`: `cargo fmt --check`, `cargo clippy --locked --all-targets` (9 old warnings, add none), `cargo test --locked`.
2. Build the signed installer locally FIRST (it compiles the NSIS script, so installer errors show before anything ships). From the repo root, Git Bash, working tree clean and NOT switching branches while it runs (~4 min):
   `CARGO_TARGET_DIR=src-tauri/target/size-build TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/bloom-enhanced.key)" TAURI_SIGNING_PRIVATE_KEY_PASSWORD="" bun run tauri build`
   Output lands in `src-tauri/src-tauri/target/size-build/release/bundle/{nsis,msi}` (the nested `src-tauri/src-tauri` is where the relative CARGO_TARGET_DIR resolves).
3. Merge to `main` (only with the user's OK; they approved on 2026-11-24): `git checkout main && git merge --ff-only <branch> && git push origin main`. Never delete branches.
4. Pick a version that has no tag yet: local tags `v0.1.0`-`v0.1.2` and upstream's `v3.x` already exist (they are old, local only), so the first LotusNotch release is **0.2.0**. `bun run release <x.y.z>` bumps package.json, tauri.conf.json, Cargo.toml and Cargo.lock together, commits "chore(release): vX.Y.Z", tags, pushes main and the tag. It refuses unless on `main`, if the tag exists, or if the bump changes nothing (same version). It needs permission to run (the auto-mode check blocked it once until the user allowed it).
5. The tag push starts the Release workflow (checks all four versions equal the tag, builds, signs with the secret, publishes the GitHub release with `latest.json`). Watch it to the end; a red run = nothing published.
6. Rebuild the local installer from the tagged `main` (step 2) so the file tested is the published version, and keep the test installer out of git (the `.log` and installer files are not tracked).
7. After it is green: `bun scripts/verify-updater.mjs v0.2.0`, then the N-1 and fresh-install checks in `RELEASE_CHECKLIST.md`. Rollback lever: mark the release pre-release.
Notes: `gh` is not installed here (use the Actions tab or the unauthenticated API `https://api.github.com/repos/IAMUCN/bloom-enhanced/actions/runs`). The version bumps cost a commit on main, so any later work starts from `main` on a new branch.
